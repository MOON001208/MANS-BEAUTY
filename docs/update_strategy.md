# 데이터 지속적 업데이트 및 관리 전략

남성 화장품 시장은 트렌드가 빠르고 새로운 리뷰가 계속 생성되므로, 데이터의 최신성을 유지하는 것이 중요합니다. 아래는 제안하는 자동화 전략입니다.

## 1. GitHub Actions를 이용한 스케줄링 (추천)
가장 비용 효율적이고 관리가 쉬운 방법입니다.

- **작동 방식**: 
  1. `.github/workflows/daily_sync.yml` 파일을 생성합니다.
  2. 매일 새벽(예: 03:00)에 Python 크롤러(`enhanced_crawler.py`)를 실행하도록 설정합니다.
  3. 크롤러는 신규 상품을 탐색하고, 기존 상품의 리뷰 수를 체크하여 서버(Supabase)와 동기화합니다.
- **장점**: 별도의 서버 운영 비용이 들지 않으며, 실행 이력을 GitHub에서 확인할 수 있습니다.

## 2. Supabase Cron + Edge Functions
Supabase 내부 기능을 사용하는 방식입니다.

- **작동 방식**: Supabase의 `pg_net` 확장이나 `Edge Functions`를 사용하여 주기적으로 특정 API를 트리거합니다. 다만, 복잡한 파이썬 크롤링 로직을 돌리기에는 GitHub Actions가 더 유연합니다.

## 3. 업데이트 로직 설계 (Incremental Update)
전체 데이터를 매번 긁는 대신 효율적으로 업데이트합니다.

- **상품 목록**: 카테고리별 1~2페이지만 주기적으로 확인하여 신규 상품이 추가되었는지 체크합니다.
- **리뷰 데이터**: 
  - DB에 저장된 각 상품의 `review_count`와 올리브영 사이트의 현재 `review_count`를 비교합니다.
  - 차이가 있을 경우에만 최신 리뷰 페이지를 긁어 `upsert`합니다.

## 4. 데이터 품질 관리
- **중복 제거**: Supabase의 `PRIMARY KEY` (Goods No, Review ID)를 활용하여 `upsert`함으로써 중복 데이터가 쌓이는 것을 방지합니다.
- **로그 모니터링**: 업데이트 실패 시 알림을 받을 수 있도록 설정합니다.

---
**제안**: 우선 로컬에서 수동으로 실행 가능한 완성형 크롤러를 제공해 드리고, 이후 원하실 경우 GitHub Actions 설정 파일 구성을 도와드리겠습니다.
