# Codex 교차검수와 로컬 수정 — 2026-09-19

## 인수 상태

기준 HEAD는 `548b7f2`. 인수 시 `ops.py verify`의 Python·웹 테스트, 추천 평가, 린트, 빌드가 통과했다.
커밋된 카탈로그 스냅샷은 상품 83개·분석 리뷰 25,818건이다. 로컬 원본 분류 캐시를 대조해
프라이머 5개·파우더/팩트 7개·쉐이딩 3개를 확인했다. 스냅샷의 라인업 중 6개 상품은 전 옵션 품절이었다.
이는 저장된 자료의 상태이며, 이번 세션의 라이브 DB 측정값이 아니다.

## 수정한 문제

- **품절 호수 정책 정정:** 사용자가 품절 호수 추천은 문제가 아니라고 확인했다. 앞서 적용했던 제외 처리를
  되돌리고 AGENTS.md도 갱신했다. 품절 옵션을 라인업에 남기고, 판매 중 옵션 우선·모두 품절일 때 가장 가까운
  호수 추천을 복구했다. 카드·상세 화면은 품절 여부를 표시한다. 같은 호수의 기획·본품 중 판매 중 옵션을
  대표로 고르는 개선은 유지한다. 품절 추천을 평가 실패로 처리하지 않으며 호수 정보 집계에도 포함한다.
- **원본 소분류 유실:** `profile_metadata.source_category`를 사용해 SQL 변경 없이 보존한다.
  상품 갱신 시 기존 리뷰 메타데이터를 유지하고, 프로필 재생성 후에도 소분류가 남는다.
  프라이머·파우더·쉐이딩을 별도 타입으로 구분하고 퀴즈에서 제외한다. 실제 파운데이션 `liquid`는 유지한다.
- **운영 검사 오판:** node_modules가 없어 웹 검사를 건너뛰면 실패한다. 공개 상품·리뷰 조회가 가능해야 하고,
  author 읽기는 HTTP 401/403 + PostgreSQL `42501`이어야 차단 확인으로 인정한다. 통신 실패·잘못된 키·누락 열은 실패다.
  배포 HTML뿐 아니라 연결된 JS도 검사하고 JWT의 service_role을 디코딩해 탐지한다. 키 값은 출력하지 않는다.
- **지표·검수 범위:** 호수 정보는 명시 호수와 상대 호수의 합집합으로 집계한다(품절 포함, 중복 제외).
  변경 없는 기준으로 crosscheck를 실행하면 경고한다.
- **키 유입 예방:** 로컬 `스크래핑 코드/`를 gitignore에 추가했다. 키 회전이나 원본 파일 수정 완료를 뜻하지 않는다.

리뷰 점수 산출 규칙 `VERSION=rules-ko-v1`은 유지한다. 저장 메타데이터 변경은 `METADATA_REVISION=6`으로
재생성되며, 유형·원본 분류 변경도 입력 해시에 포함한다. **수집 수동 / 프로필만 자동 갱신** 설정은 유지했다.

## 적용 범위와 제한

검증: Python 회귀 테스트 66개, 웹 테스트 20개, 83개 상품 스냅샷 기반 페르소나 12개 평가,
린트, 정적 빌드 및 번들 키 검사를 통과했다. 평가의 필수 조건 위반은 0건, 주장 근거 추적률은 100%였다.
권한 검사 기준은 [Supabase 공식 오류 코드](https://supabase.com/docs/guides/api/rest/postgrest-error-codes)를 확인했다.

이번 변경은 로컬 파일에만 있다. DB 쓰기·리뷰 추가 수집·배포는 하지 않았다.
`ops.py health`와 `ops.py status`는 DB 연결/조회 단계에서 URLError로 실패했다. 최초 원인은 Windows
샌드박스의 소켓 접근 거부(WinError 10013)였다. `.git/index.lock` 생성도 Permission denied라 점유·완료
커밋과 푸시를 수행할 수 없었다. 승인 정책 never이므로 추가 권한 요청도 하지 않았다.

사용자의 `.claude/settings.local.json`, 레거시 코드 2개, 개인 문서들은 수정하지 않았다.

## 네트워크·Git 쓰기가 가능한 세션에서 이어갈 순서

1. 다른 모델이 이 로컬 diff를 검수한다. 변경 파일은 작업보드의 Codex 완료 항목과 새 `tests/test_ops.py`를 포함한다.
2. 상품만 수동 수집해 기존 DB의 원본 소분류를 채운다. 접근 제한 시 일부 상품만 적용됐는지 보고서를 확인한다.
3. `run_pipeline.py --profiles-only --write`로 프로필 r6를 생성한다. 이미 기록된 리뷰만 사용하며 유료 API가 필요 없다.
4. `web`에서 `npm.cmd run snapshot`으로 실제 DB 스냅샷을 갱신하고 `ops.py verify`, `health`, `status`를 실행한다.
5. 변경 파일만 명시해 커밋·푸시하고 CI·배포 후 health를 다시 확인한다. 사용자 변경을 함께 커밋하지 않는다.
