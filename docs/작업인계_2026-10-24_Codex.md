## 수집 경로 수정

직접 HTTP 요청은 두 상품의 리뷰 수집 단계에서 403으로 멈췄다. 상품 상세·리뷰 통계는 조회됐지만, 화면과 동일한 리뷰 목록 요청을 보내도 직접 HTTP에서는 403이었다.

Crawl4AI로 비로그인 Chromium에서 실제 리뷰 탭을 열어 **동일 cursor API가 HTTP 200·10건**을 반환하는 것을 확인했다. 같은 브라우저에서 50건 요청도 HTTP 200으로 확인하고 선택 옵션 `--browser`를 추가했다.

- `scraper/browser.py`: Crawl4AI 브라우저 안에서 요청하고 기존 수집기에 응답을 전달한다. 로그인 프로필은 저장하지 않는다.
- `scraper/crawler.py`: 명시적인 `--browser` 선택 시에만 새 전송 경로를 사용한다. 자동 우회·자동 재시작은 없다.
- 기존 정렬·옵션 수집, 중복 제거, 상품 ID 보존, 커서 저장, 로그인 요구·접근 제한 중단 규칙을 재사용한다.
- 브라우저의 실제 응답 헤더를 읽어 JavaScript에 노출되지 않는 `Retry-After`도 반영한다.
- 점수 규칙과 프로필 버전은 변경하지 않았다.
- 브라우저 순회는 10-24 00:53~01:04 KST, 6개 완료·오류 0건. 이후 최종 헤더 처리 버전으로 실시간 통계 조회도 통과했다.

## 이후 수동 누적 수집

수집은 사용자가 PC에서 수동 실행하고, 예약 작업은 기존처럼 저장된 리뷰의 프로필만 갱신한다. 새 수집 자동화는 만들지 않았다. 같은 PC의 커서를 유지한다.

```powershell
# 저장소 루트에서 실행. 기본 --write 생략 시 미저장 확인 모드.
.venv\Scripts\python.exe code/7_advanced_recommender/run_pipeline.py --browser --write --max-review-pages 2 --delay 8 --max-seconds 5400 --skip-ingredients
.venv\Scripts\python.exe code/7_advanced_recommender/run_pipeline.py --write --profiles-only
.venv\Scripts\python.exe code/7_advanced_recommender/ops.py health
.venv\Scripts\python.exe code/7_advanced_recommender/ops.py status
```

특정 상품만 수집하려면 `--product 상품ID`를 반복 지정한다. 접근 제한·로그인 요구·긴 대기 지시가 나오면 중단 상태를 확인한다. 전체 프로필 단계는 연관 상품의 신규 리뷰까지 반영하기 위한 것이다.
