# 추천 개선: 자연스러움과 항목별 근거 (2026-10-24)

운영 범위는 남성 베이스 메이크업이며 상품 87개·고유 리뷰 33,954건을 사용했다. 새 수집을 수행하거나 리뷰 귀속을 바꾸지 않았다. 이번 변경은 rules-ko-v3 / metadata r8이다.

## 구현

1. **화장 티·묻어남·들뜸을 직접 집계** — `pipeline/wear.py`에서 명시적인 자연스러움, 착용 후 묻어남, 들뜸·뭉침·끼임 표현을 구분한다. 피부 자기소개·기대·가정·다른 제품·이중 부정은 보수적으로 제외한다. 브러시 때문에 손에 안 묻는 사용 편의성을 묻어남 방지 성능으로 세지 않는다.
2. **점수와 근거량 분리** — 명확한 긍정 리뷰 4, 부정 리뷰 2를 평균하되 항목별 고유 근거 3건 미만이면 null. 같은 리뷰 안에서 긍정/부정이 공존하면 mixed로 보존하고 점수에서는 제외한다. 긍정·부정·mixed 각각 원문 리뷰 ID를 기록한다.
3. **선택한 항목의 근거를 순위에 반영** — 6개 중요도(1~5, 1은 무시)에 기존 기능 배점 30을 배분한다. 근거 지수 n/(n+5)로 적은 근거의 평가를 순위에서만 중립값 쪽으로 완화한다. 정보 없는 항목을 최저 품질로 취급하지 않고 표시·저장은 계속 null이다. 기존 전체 리뷰 수 최대 +5는 선택 항목의 근거 보강으로 바꿨다. 피부·고민·호수 기준은 유지한다.
4. **옵션별 근거 확인** — 원문 옵션명 238개 그룹의 새 사용감 근거를 따로 집계하고 상세 화면에서 전환할 수 있게 했다. 임의 호수 환산·옵션명 통합·현재 판매 옵션으로의 자동 대응은 하지 않는다. 리뉴얼 전후는 구분할 근거가 없으므로 확인했다고 주장하지 않는다. 추천 순위는 상품 전체 집계다.
5. **사람 평가 도구** — 고정한 v2 상위 3개와 v3 상위 3개를 같은 데이터 범위에서 비교하는 15개 사례를 준비했다. 좌우 방식 이름을 숨기고 같은 자료의 근거를 보여준다. 다른 목록 8개를 먼저 제시하고 동일 순서 7개는 별도 집계한다. 응답은 브라우저에 임시 저장하며 사람이 확인 후 파일로 내보낸다. 실제 응답 0건으로, 가짜 라벨이나 자동 채점을 넣지 않았다.

## 배점과 남은 사람 평가

n/(n+5)의 5, 기존 배점, 기본 중요도 3은 정책값이다. 사람이 더 선호한다는 평가로 학습·검증한 최적 가중치가 아니다. 정보 부족은 순위 산술에서만 중립으로 두며 제품 효능 점수를 생성하지 않는다. 분류기는 한국어 문맥을 놓칠 수 있고, 판매 옵션이나 리뉴얼을 임의로 같은 것으로 취급하지 않는다.

[사람 비교 평가](https://moon001208.github.io/MANS-BEAUTY/recommendation-review.html)에서 실제 응답을 모아 `npm run review:report -- 응답.json`으로 집계한다. 같은 응답의 중복 저장은 다시 세지 않고, 평가 세트가 다른 파일은 거부한다. 동일 순서 사례도 우열에 포함하지 않는다. 이후 충분한 평가 이유를 검토해 배점을 조정하고 평가에 사용하지 않은 사례에서 다시 확인해야 한다. 이 단계는 사람 응답을 기다리는 중이다.
